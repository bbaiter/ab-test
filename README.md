

# A/B Testing & Product Analytics
Проект посвящен полному циклу дизайна и анализа A/B-теста для e-commerce продукта. Была сформулирована продуктовая гипотеза, расчитан размер выборки (в соответствии с заданной мощностью на уровне 80%), проведен А/А тест разделения выборки, дана оценка основного эффекта и метрик-ограничителей, а также был создан интерактивный дашборд на Streamlit. Данные сгенерированы синтетически для контроля истинного эффекта.

## TL;DR (Ключевые результаты)
*   **Конверсия(основная метрика):** Зафиксирован статистически значимый рост на **+1.93 п.п.** (с 10.08% до 12.00%), p-value = 0.0098. 95% CI: [0.46, 3.39] п.п.
*   **Средний чек на человека(ARPU - метрика ограничитель):** Рост выручки на пользователя составил **+56.47 руб.**, однако эффект не достиг уровня значимости (p-value = 0.2073) из-за высокой дисперсии метрики.
*   **Размер выборки:** Для детектирования целевого эффекта (+2 п.п.) с мощностью 80% и \(\alpha=0.05\) потребовалось по **3532 пользователя** в каждой группе (изначально планировалось 2000, но мощность падала до 50%).
*   **Бизнес-решение:** Рекомендуется внедрение предполагаемого баннера  так как конверсия выросла, а метрика-ограничитель не показала критического падения.

## Описание директорий и файлов
*   `context.md` — содержит бизнес-контекст (баннер бесплатной доставки) и систему метрик (Конверсия -- основная, Средний чек -- ограничительная).
*   `data/` — содержит сгенерированный датасет. Данные включают `user_id`, `group`, `platform`, факт покупки (`if_buyer`) и сумму (`revenue`).
*   `scripts/generator.py` — скрипт для генерации данных с заданными параметрами (базовая конверсия, AOV, размер выборки).
*   `scripts/design_analysis.py` — расчет чувствительности теста (MDE) и построение графиков зависимости мощности от размера выборки.
*   `scripts/aa_test.py` — симуляция (1000 итераций) для проверки отсутствия систематической ошибки в тесте (FPR должен быть ~5%).
*   `scripts/ab_test.py` — расчет p-value, доверительных интервалов и Lift для основной и guardrail-метрик.
*   `scripts/dashboard.py` — интерактивный интерфейс для стейкхолдеров (визуализация дизайна и результатов теста).

## Основные выводы и инсайты
**1. Дизайн и валидация эксперимента**
*   **Рассчет мощности:** На выборке в 2000 юзеров тест способен поймать только эффект от +2.66 п.п. Для целевого эффекта в +2 п.п. требовалось 3532 юзера на группу.
*   **A/A тест:** Прогон 1000 симуляций без эффекта показал долю ложноположительных срабатываний (FPR) на уровне 5%, что подтверждает корректность выбранного статистического критерия.
*   **Оценка качества разбиения:** Проверка качества сплитования (Chi-square) показала отсутствие перекосов в размерах групп (p=1.000) и в распределении платформ Web/iOS/Android (p=0.198).

**2. Результаты А/Б теста**
*   **Конверсия:** Тест показал, что баннер мотивирует пользователей завершать покупку. Доверительный интервал `[0.46, 3.39]` не включает ноль, эффект надежен на уровне значимости 5%.
*   **Средний чек ан пользователя:** Точечная оценка выручки выросла на 56 руб. Однако из-за большого количества нулевых чеков (90% пользователей ничего не купили) стандартное отклонение слишком велико. Широкий доверительный интервал `[-31.31, 144.24]` не позволяет заявить о статзначимом росте выручки на текущей выборке.

## Установка и запуск
1. Клонируйте репозиторий и перейдите в папку проекта:
```bash
git clone <url_репозитория>
cd ab-test-proj
```
2. Создайте и активируйте виртуальное окружение:
```bash
python3 -m venv venv
source venv/bin/activate
```
3. Установите зависимости:
```bash
pip install -r requirements.txt
```

## Использование
Пайплайн запускается последовательно из папки `scripts`:

**Шаг 1: Генерация данных**
```bash
python3 generator.py
```

**Шаг 2: Анализ дизайна (MDE и Power)**
```bash
python3 design_analysis.py
```

**Шаг 3: Валидация (А/А тест)**
```bash
python3 aa_test.py
```

**Шаг 4: Анализ основного теста (А/Б)**
```bash
python3 ab_test.py
```

**Запуск интерактивного дашборда**
```bash
streamlit run dashboard.py
```

## Ограничения (Limitations)
*   **Синтетические данные:** В проекте используется генератор случайных чисел с заложенным эффектом разницы конверсий. Это сделано намеренно для проверки гипотез (оценки ошибок I и II рода), однако не учитывает сложные поведенческие паттерны реальных пользователей (например, эффект новизны).
*   **Высокая дисперсия ARPU:** Для доказательства значимости роста выручки на такой метрике в реальной жизни потребовалось бы значительно больше трафика.
